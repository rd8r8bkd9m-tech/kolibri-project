
# Kolibri: 30-Day World-Class Plan

## Цель

За ближайшие 30 дней довести Kolibri не до "ещё одного чат-бота", а до
демонстрационно сильного класса ИИ:

- C-core first
- формульная память вместо весов
- честное обучение на входящих данных
- рой как ускоритель обучения
- прозрачные метрики `1 vs 10`

## Что считаем главным результатом

К концу цикла Kolibri должен уметь:

1. Принимать текст и URL в живую формульную память.
2. Автоматически распространять новые знания по 10-узловому рою.
3. Показывать, что `10 узлов` учатся быстрее `1 узла`.
4. Давать source-grounded ответы по-русски без выдумки.
5. Работать через production frontend на `kolibriai.ru`.

## Приоритеты

### 1. Живой цикл обучения

Сделать устойчивый контур:

`ingest -> live formula memory -> refresh -> swarm metrics -> user-visible answer`

Это важнее любых новых декоративных режимов.

### 2. Качество ответов

Усилить:

- выбор релевантной формулы
- русскоязычную сборку ответа
- честный отказ при нехватке знания
- отделение smalltalk от знания

### 3. Рой как доказуемое преимущество

Нужно уметь в любой момент показать:

- сколько документов в живой памяти
- что изменилось после ingest
- как быстро сходится `1 узел`
- как быстро сходится `10 узлов`

### 4. Evals как закон

Всё развитие вести через измерения:

- answer quality
- false answer rate
- hit ratio на knowledge memory
- refresh latency
- swarm delta `1 vs 10`

### 5. Отложенный Visual Track

Визуальный контур зафиксирован, но временно не является главным драйвером 30-дневного цикла.

Что уже сделано:

- локальный browser-side фотоанализ в production frontend
- local-first `vision/analyze` в backend
- отказ от зависимости на внешний vision как обязательный путь

Что вернём позже отдельным треком:

- более глубокий локальный OCR
- серверные visual detectors
- обучение C-core на визуальных признаках и формулах изображения
- связка `image -> formula memory -> swarm propagation`

## План по неделям

### Неделя 1

- live formula memory без потери данных при deploy
- ingest text/url из production
- авто-refresh после ingest
- статус refresh в API/UI

### Неделя 2

- улучшение C-core answer composer
- stricter no-fabrication mode
- better topic matching для `что такое X`
- curated evals на русских доменах

### Неделя 3

- роевой перенос не только формул, но и свежих ассоциаций/документов
- online benchmark на новых входящих знаниях
- фоновые задачи обновления памяти

### Неделя 4

- hardening production path
- demo-сценарий "обучили на новом знании -> рой ускорил усвоение -> чат отвечает"
- финальные сравнительные отчёты

## Нельзя распыляться

Не тратить основной темп на:

- лишние UI-эксперименты
- побочные сервисы
- абстрактные AGI-слои без измеримого эффекта

## Что делаем прямо сейчас

Текущий прогресс плана: `100%` в рамках зафиксированного 30-дневного scope.

Уже закрыто:

1. Автоматический refresh после ingest.
2. Видимый refresh status в API и UI.
3. Curated evals на русских доменах и жёстче topic-specific проверки.
4. Видимый `domain_delta` после ingest в runtime status и UI.
5. Видимый `knowledge refresh delta` после refresh:
   рост документов, `hit_ratio`, и преимущества `10 узлов` над `1`.
6. Demo-path `ingest -> force refresh -> before/after report`
   с доменными дельтами и сравнением `1 vs 10` по новому знанию.
7. User-visible chat demo path:
   новое знание ingested, рой пересчитан, ответ ядра и краткий отчёт возвращаются одним вызовом.
8. Production UI уже выводит chat demo path прямо из центрального composer.
9. Базовый русскоязычный domain-sweep на production path переведён в `c-core-formula`:
   `математика`, `медицина`, `география`, `философия`, `биология`, `физика`, `астрономия` -> `7/7`.
10. Расширенный domain-sweep на production path тоже переведён в `c-core-formula`:
   `анатомия`, `программирование`, `патология`, `терапия`, `химия`,
   `история`, `экономика`, `право`, `алгоритм`, `физиология` -> `10/10`.
11. Падежные русские формулировки тоже переведены в production `c-core-formula`:
   `объясни физику простыми словами`, `расскажи о химии`, `расскажи о праве`.
12. Python bridge синхронизирован с C-core:
   `расскажи о ...` больше не уходит в `greeting/topic-overview`, а `объясни ...`
   больше не падает в `quick-explain-fallback`.
13. Фокусные русские вопросы тоже переведены в production `c-core-formula`:
   `что изучает история`, `что изучает химия`, `чем занимается право`.
14. Эти новые классы запросов закреплены в quality evals, чтобы не деградировали дальше.
15. Demo-сравнение `1 узел vs 10 узлов` стало явным и user-facing:
   в ответе demo теперь есть отдельный сравнительный summary по усвоению знания.
16. Последний demo теперь сохраняется в runtime status и виден в swarm UI
   даже вне чата, как постоянный before/after отчёт по новому знанию.
17. После chat-demo swarm screen автоматически синхронизируется и показывает свежий результат
   без ручного повторного обучения и без ручного похода в API.
18. Для уже обученных доменов добавлен ещё один естественный класс русских вопросов:
   `как устроено / как устроен / как устроена ...` теперь идёт через `c-core-formula`,
   а не через общий fallback.
19. Для уже обученных доменов добавлен и причинный класс вопросов:
   `почему важно ...` и `зачем нужно ...` теперь тоже идут через `c-core-formula`
   на основе формульной памяти, а не через внешний слой.
20. Русскоязычный answer composer в `C-core` теперь собирает более длинные
   двухпредложные ответы для `расскажи о ...`, `как устроено ...`, `почему важно ...`,
   и это уже подтверждено на production path.
21. Причинный класс `почему важно / зачем нужно` расширен с одного домена
   на базовый набор знаний: ядро уже формирует такие ответы как минимум для
   `право`, `математика` и `медицина` через `c-core-formula`.
22. Production bridge к `kolibri_infer_cli` hardened:
   decode-bug на грязном UTF-8 в stdout исправлен, и публичный path снова
   стабильно отвечает на `почему важна математика` и `зачем нужна медицина`.
23. Добавлен длинный объяснительный класс запросов:
   `расскажи подробно о ...` теперь идёт через `c-core-formula`,
   а answer composer в C-core собирает более глубокий ответ из нескольких фрагментов.
24. Добавлен knowledge-style класс запросов:
   `что ты знаешь о ... / об ... / про ...` теперь тоже идёт через `c-core-formula`
   без ухода в `topic-overview` и прочие fallback-ветки.
25. Финальный production hardening по этому циклу завершён:
   новые query-классы закреплены тестами, выкачены на `kolibriai.ru` и подтверждены
   живыми public smoke-запросами.

Этот плановый цикл закрыт. Следующий активный блок уже относится к следующему этапу, а не к добивке текущего scope:

1. Расширение доменного покрытия `c-core-formula` за пределы текущего набора.
2. Переход от двух-трёх предложений к действительно многоабзацным ответам ядра.
3. Следующий слой reasoning-вопросов за пределами текущих definitional/causal шаблонов.
4. Новый цикл demo/evals уже для более сложных задач, а не для базового production scope.
