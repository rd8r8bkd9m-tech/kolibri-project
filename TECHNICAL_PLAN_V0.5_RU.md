# Технический план развития Kolibri v0.2 → v0.5

## Обзор

**Цель**: Развитие от базового обучения паттернам (v0.2) до гибридной архитектуры "Умного ассистента" (v0.5) за 6 месяцев.

**Текущее состояние (v0.2)**:
- ✅ Базовое обучение паттернам (kolibri_learn.c)
- ✅ Формульная память (formula.c, formula_logic.c)
- ✅ Контекст диалога (context_window.c)
- ✅ Сжатие данных с пониманием смысла (compress.c, semantic_digits.c)
- ✅ Детерминированная генерация (kolibri_gen.c)
- ✅ Формат .kgen (kolibri_generative.c)

**Целевое состояние (v0.5)**:
- 🎯 Гибридная архитектура (Символика + Нейросеть)
- 🎯 Решение логических задач
- 🎯 Код-генерация
- 🎯 Глубокий анализ файлов .kgen
- 🎯 Уровень "Умного ассистента"

## Компонент A: Модуль генерации кода (code_gen.c)

### Описание
Расширение существующего генератора текста для генерации программного кода с соблюдением синтаксиса и семантики языков программирования.

### Технические задачи

#### A.1. Интеграция с существующим generation.h (2 недели)
- [ ] Использовать существующий интерфейс `KolibriGenerationContext`
- [ ] Добавить стратегию `KOLIBRI_GEN_CODE` в enum `KolibriGenerationStrategy`
- [ ] Расширить `KolibriGenerationCandidate` для хранения AST-узлов

#### A.2. Синтаксические шаблоны для языков (3 недели)
- [ ] Создать базу синтаксических паттернов для C/Python/JavaScript
- [ ] Реализовать парсер простых грамматик (BNF-подобных)
- [ ] Интеграция с формульным сжатием для шаблонов кода

**Структура данных**:
```c
typedef struct {
    char language[32];
    char *grammar_rules;      // BNF-правила
    size_t num_rules;
    KolibriSemanticPattern *code_patterns;
    size_t num_patterns;
} KolibriCodeSyntax;
```

#### A.3. Семантический анализ кода (3 недели)
- [ ] Извлечение паттернов из обучающего корпуса кода
- [ ] Построение графа зависимостей между функциями
- [ ] Контекстное понимание типов данных

#### A.4. Генерация с валидацией (2 недели)
- [ ] Пост-генерационная проверка синтаксиса
- [ ] Исправление очевидных ошибок
- [ ] Интеграция с компилятором/интерпретатором для обратной связи

#### A.5. Тестирование и документация (2 недели)
- [ ] Unit-тесты для каждого языка
- [ ] Бенчмарки качества генерации
- [ ] Примеры использования

### Оценка времени: **12 недель (3 месяца)**

### Зависимости
- Требуется компонент C (парсер .kgen) для загрузки обучающих данных
- Требуется компонент B (символический движок) для логической валидации

### Метрики успеха
- Генерация рабочего кода для простых задач (калькулятор, сортировка, парсинг)
- Синтаксическая корректность > 90%
- Способность продолжать заданный фрагмент кода

- [ ] Взвешивание результатов от обоих подходов

#### B.6. Тестирование (3 недели)

## Компонент C: Парсер .kgen файлов

### Описание
Глубокий анализ и обработка файлов формата .kgen для извлечения знаний, мета-данных и сжатых паттернов.

### Технические задачи

#### C.1. Спецификация формата .kgen (1 неделя)
- [ ] Документирование текущей структуры (из kolibri_generative.c)
- [ ] Определение расширений для v0.5
- [ ] Создание тестовых файлов разных версий

**Текущая структура** (из анализа кода):
```c
typedef struct {
    uint32_t magic;           // 0x4B47454E "KGEN"
    uint32_t original_size;
    uint32_t l5_hash;
    uint16_t l5_params;
    // ... уровни L1-L5 ...
} GenerativeHeader;
```

#### C.2. Базовый парсер (2 недели)
- [ ] Чтение и валидация заголовка
- [ ] Проверка контрольных сумм
- [ ] Извлечение метаданных

#### C.3. Декомпрессия уровней (3 недели)
- [ ] Обратное прохождение уровней L5→L4→L3→L2→L1
- [ ] Восстановление оригинальных данных
- [ ] Обработка ошибок и повреждённых файлов

#### C.4. Извлечение семантических паттернов (3 недели)
- [ ] Парсинг встроенных формул
- [ ] Извлечение ассоциаций текст↔хеш
- [ ] Построение графа знаний из файла

**Новый API**:
```c
typedef struct {
    char version[16];
    uint32_t original_size;
    uint32_t compressed_size;
    double compression_ratio;
    
    KolibriFormula *formulas;
    size_t num_formulas;
    
    KolibriSemanticPattern *patterns;
    size_t num_patterns;
    
    void *raw_data;
    size_t raw_data_size;
} KolibriKgenDocument;

int k_kgen_parse(const char *filename, KolibriKgenDocument *doc);
int k_kgen_extract_knowledge(KolibriKgenDocument *doc, 
                             KolibriCorpusContext *corpus);
```

#### C.5. Индексация и поиск (2 недели)
- [ ] Построение индекса по содержимому .kgen
- [ ] Поиск по семантическим паттернам
- [ ] Быстрый предпросмотр без полной декомпрессии

#### C.6. Инструменты CLI (2 недели)
- [ ] `kolibri_kgen inspect <file>` - показать метаданные
- [ ] `kolibri_kgen extract <file> <output>` - декомпрессия
- [ ] `kolibri_kgen merge <file1> <file2> <output>` - слияние
- [ ] `kolibri_kgen search <pattern> <directory>` - поиск

#### C.7. Тестирование (2 недели)
- [ ] Тесты на округление (сжал→распаковал=оригинал)
- [ ] Тесты производительности на больших файлах
- [ ] Fuzzing для устойчивости

### Оценка времени: **15 недель (3.5 месяца)**

### Зависимости
- Использует существующие compress.c, formula.c
- Необходим для компонента A (загрузка обучающих данных)

### Метрики успеха

### Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Сложность гибридной архитектуры | Высокая | Высокое | Начать с простого чередования, не глубокой интеграции |
| Производительность логического вывода | Средняя | Среднее | Раннее профилирование, оптимизация горячих путей |
| Качество генерации кода | Средняя | Высокое | Фокус на 1-2 языка сначала, не все сразу |
| Scope creep | Высокая | Среднее | Строгое следование MVP, фичи в v1.0 |

## Заключение

План реалистичен при наличии 1-2 разработчиков на 6 месяцев. Ключевой риск - сложность гибридной архитектуры, поэтому рекомендуется начинать с простой интеграции и постепенно углублять.

**Рекомендуемый порядок реализации**:
1. **C** (парсер .kgen) - фундамент для загрузки знаний
2. **B** (символический движок) - независим, может разрабатываться параллельно
3. **A** (генерация кода) - требует C и частично B
4. **D** (интерфейс) - требует все предыдущие для полноценной работы

**MVP через 3.5 месяца**, **полный релиз v0.5 через 6 месяцев**.
